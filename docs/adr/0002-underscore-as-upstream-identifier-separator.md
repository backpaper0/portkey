# アップストリーム識別子のセパレータに`_`を採用する

v1実装では、アップストリーム識別子(`<ホスト名>~<ポート>`)のセパレータに`~`を採用していたが、実機検証(Chromium)により`web~3000.localhost`のようなホスト名が`*.localhost`のワイルドカード名前解決自体に失敗し(`net::ERR_NAME_NOT_RESOLVED`)、アップストリームへ到達できないことが判明した。代替として`-`も検討したが、ホスト名部分は元々ハイフンを許容する(`my-app.internal`等)ため、`-`をセパレータに採用すると`my-app-3000`のような文字列で「どのハイフンがセパレータか」が一意に定まらず、識別子のパースが曖昧になる。

以上の検証結果から、セパレータには`_`を採用する。ホスト名部分の許容文字集合(`[a-z0-9-]`、RFC 952/1123準拠)には`_`が含まれないため、識別子中に`_`がちょうど1回だけ出現するという単純な規則のままホスト名とポートを曖昧性なく分離でき、かつ実機検証でブラウザ・DNS層を問題なく通過することを確認済み。

## Considered Options

- `~`: v1初期実装で採用していたが、Chromeの`*.localhost`ワイルドカード名前解決が拒否するため致命的に不採用。
- `-`: ブラウザ・DNS層は問題なく通過するが、ホスト名自体が`-`を含みうるためパースが曖昧になり不採用。
- `_`: ホスト名の許容文字集合に含まれず曖昧性がなく、実機検証でも問題なし。採用。
